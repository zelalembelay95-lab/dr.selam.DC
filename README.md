# Dr Selam Dental Clinic: website and appointment system

```
frontend/   Website (index.html) + logo files. Runs as-is in demo mode (data kept in the browser).
backend/    Node + Express API for Render. Data in Supabase (Postgres), login and roles in Firebase Auth.
  schema.sql  Database tables, run once in Supabase
render.yaml Render blueprint for the API and the static site
```

How the pieces fit: the website talks only to the API. The API checks the Firebase login token, then reads and writes Supabase with the service role key. The website never sees that key.

## 1. Supabase (database)
1. Create a project at supabase.com.
2. SQL Editor > New query > paste `backend/schema.sql` > Run. This creates `patients` (card numbers DS-0001, DS-0002 ... are generated by the database) and `appointments`, and blocks double-booking of a time slot.
3. Project Settings > API: copy the **Project URL** and the **service_role** key. The service_role key is secret: it goes only in Render's environment variables, never in the website or GitHub.
4. Row Level Security is switched on with no public policies, so nobody can reach the data except through your API.

## 2. Firebase (login and roles)
1. Create a project at console.firebase.google.com and enable Authentication > Email/Password. You do not need Firestore.
2. Project settings > Service accounts > Generate new private key. Keep the JSON secret.
3. Create the first admin (run on your computer):
   `cd backend && npm install && FIREBASE_SERVICE_ACCOUNT='<json on one line>' node make-first-admin.js you@mail.com StrongPassword`
4. Roles are custom claims: admin, ceo, manager, receptionist. The admin adds other staff with `POST /api/staff`.
5. Patient logins: staff call `POST /api/patients/DS-0001/account` with the patient's email and a password. This links the login to the card number.

## 3. Render
1. Push this folder to GitHub.
2. Render > New > Blueprint > pick the repository.
3. On `dr-selam-api` set `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `FIREBASE_SERVICE_ACCOUNT` and `ALLOWED_ORIGINS` (your site address).
4. Check `https://<your-api>.onrender.com/health` returns `{"ok":true}`.

## 4. Cloudflare (domain and DNS)
1. Add your domain to Cloudflare and change the registrar's nameservers to Cloudflare's.
2. Render > dr-selam-site > Settings > Custom Domains: add `yourdomain.com` and `www`.
3. Cloudflare > DNS: add the CNAME records Render shows. Optionally add `api` pointing to the API service.
4. SSL/TLS mode: Full (strict), proxy on.

## 5. Connecting the website to the API
`frontend/index.html` is already wired for the live system — it calls the API and uses Firebase login, it just needs your project's details. Open the file, find the `CONFIG` block near the top of the `<script>` section, and fill in:

```js
const CONFIG = {
  API_BASE: "https://YOUR-RENDER-API.onrender.com",   // your Render API's URL
  FIREBASE: {
    apiKey: "...",        // Firebase console > Project settings > your web app
    authDomain: "....firebaseapp.com",
    projectId: "...",
    appId: "..."
  }
};
```

These four Firebase values are public identifiers (safe to ship in the page) — never put the Firebase **service account** JSON or the Supabase **service_role** key here; those stay on Render only. Until `CONFIG` is filled in, the site runs safely with clear on-page notices instead of a broken demo: booking shows "connect the backend," and login explains it isn't wired up yet.

## API
| Method | Path | Who |
|---|---|---|
| GET | /api/slots?date=YYYY-MM-DD | public |
| POST | /api/public/appointments | public (guest booking, auto-registers the patient) |
| GET, POST | /api/appointments | signed in (staff see all, patients see own) |
| PATCH | /api/appointments/:id | staff any status; patients cancel their own |
| GET | /api/patients?search= | staff |
| POST | /api/patients | admin, manager, receptionist |
| POST | /api/patients/:card/account | admin, manager, receptionist |
| GET | /api/staff | admin, ceo, manager |
| POST | /api/staff | admin |
